# 给设计助手的沉浸感建议

写给做界面和交互设计的助手（ChatGPT）。作者是负责运维和功能的 Claude，写于 2026-10-04。

用户的要求是把界面和交互做得更沉浸，并且说了你可以修改所有东西：代码、样式、文案、页面结构都可以动。下面第 1 到第 3 节是建议和现状，不是限制，取舍由你和用户决定。第 4 节是用户点名要保留、之后会用的 iPod 播放器在哪里。第 5 节是事实：改的时候如果碰到这些地方，线上会坏，或者会违反用户已经定下的规则。

## 1. 先读什么

- `AGENTS.md`：所有助手共用的规则和 PR 流程。`main` 一合并就上线，有真实用户。
- `docs/interaction-roadmap.md`：用户最初写的沉浸式路线图（第三人称仪式感、推门、走向座位、插入事件）。这是方向的来源，下面的建议都是在它的基础上说「现在缺什么、先做哪个」。
- `docs/visual-asset-guidelines.md`：场景图的画风和命名规范。
- `docs/animation.md`：两套已经装好的动画工具怎么用。
- `docs/progress.md`：当前状态、谁在做什么、改动日志。

## 2. 现在的体验（实际情况，不是计划）

- 六个场景：入口、点单、选座、设定、专注、完成（`src/scenes/`）。每个场景是一块半透明面板，盖在全屏背景图上。
- 背景由 `src/components/SceneBackdrop.jsx` 负责：每个场景 3 张同构图的 WebP，每 7.2 秒淡入淡出换一张。它已经支持 `media.video`（静音循环视频），但现在没有任何场景用视频。
- 场景之间是瞬间切换，没有过渡。入口点「推门进入」时会放脚步声、木门声和门铃（分别在 0、450、800 毫秒），但画面在第 0 毫秒就已经换成点单页了。
- 路线图里的 `doorOpening`、`walkingToSeat` 两个过渡场景还没做。停滞提醒和休息提议已经做了（专注页的 `InterventionCard`）。
- 时间档（早晨、白天、夜晚）现在只换声音，画面始终是雨夜。用户说过画面这部分交给你。
- 专注页是「大号倒计时加一个混音器侧栏」。桌面端侧栏一直展开，窄屏是抽屉。
- 已经装好但还没接到任何页面上的东西：Motion（界面动效，`src/motion/`）和 PixiJS（场景画布，`src/canvas/`）。
- 已经有但页面没用到的美术素材：`public/assets/characters/` 里的主角和店员设定图，仓库根目录 `cafe-artifacts/` 里的 21 张人物立绘（咖啡师递咖啡、擦杯子，四位顾客的坐姿和站姿，主角正面、侧面、背面）和一张咖啡店全景。

## 3. 建议，按效果和工作量排序

### 3.1 给场景切换加过渡（效果最大，工作量最小）

现在最出戏的地方是切换：声音在讲「推门、走进去」，画面却是硬切。建议：

- 入口到点单做成一段 1 到 1.5 秒的「推门」：画面向门的方向推近并变暗，再从暗处亮出店内。把画面节奏对上已有的三个声音时间点。
- 选座到设定做成「走过去坐下」：背景交叉淡化加一点横向位移。
- 其余切换用统一的淡入加轻微上移。
- 实现位置：`src/App.jsx` 的 `renderScene()` 外面包 `AnimatePresence`，动作用 `src/motion/presets.js` 里现成的 `sceneChange`，并在 `src/main.jsx` 用 `MotionRoot` 包住应用。
- 每段都要短、安静、可以跳过（路线图的原则）。系统开了「减少动态效果」时只留淡入淡出，`MotionRoot` 已经处理了这一点。

### 3.2 专注页：让界面退后，让房间在前

专注页是用户停留时间最长的一页，现在更像一个设置面板。建议：

- 几秒没有操作后，除了倒计时和任务之外的东西都淡出；移动鼠标、按键或触屏时再回来。
- 桌面端的混音器也做成可以收起的，默认收起，让背景露出来。
- 倒计时现在是页面正中的特大号数字（4.55rem，已经是等宽数字）。字号可以小一些，位置可以不在正中，让它像桌上的一个物件而不是页面的主角。
- 进度不要用进度条，用房间里的东西表达：杯子里的咖啡慢慢变少，热气变淡，窗外天色变化。
- 提供一个「只留时间」的极简状态和一个全屏按钮（浏览器的 Fullscreen API，不涉及任何数据）。

### 3.3 画面跟着时间档变

用户明确把这件事留给了设计。两条路：

- 省事的做法：在背景图上叠一层按时间档变化的色调层（早晨偏暖偏亮，白天中性，夜晚保持现状），雨的效果单独做成一层，只在雨声滑块大于 0 时出现。不需要新图。
- 完整的做法：每个场景按时间档各出一组图，放 `public/assets/scenes/<场景>/<时间档>/01-03.webp`，在 `src/data/media.js` 的 `getSceneMediaKey` 里加上时间档。
- 当前时间档在 `useSoundscape` 返回的 `sound.timeSlot` 里。
- 用户定的规则：时间档由访客自己选，不按访客的本地时间自动切换。

### 3.4 让画面对声音有反应

现在是「一张图加一排滑块」，两者互不相干。把它们连起来最能让人觉得这是同一个地方：

- 雨声滑块控制窗上雨痕的密度；街声高时偶尔有车灯扫过；杯碟声对应桌上的杯子冒热气；鸟叫只在早晨出现。
- 每条声音的音量（0 到 1）在 `useSoundscape` 返回的 `sound.layerMix` 里，可以直接驱动画面。
- 用 `src/canvas/` 的 `CanvasStage` 叠在背景上。Pixi 约 200 KB（gzip），是懒加载的，只有用到的页面才会下载；加载中和失败时显示静态图。

### 3.5 把控制做成房间里的物件

iPod 播放器（见第 4 节）是一个很好的样板：它是一个可以拿在手里的东西，而不是一个表单。同样的思路可以用在别处：

- 混音器不必是一列滑块。可以是桌上的几样东西（窗对应雨，杯子对应店里的人声，iPod 对应音乐），点开才出现细调。
- 选座可以直接在咖啡店全景图上点座位，而不是在卡片列表里选。
- 无论外观怎么变，下面要保留真正的滑块和按钮语义（见第 5 节的无障碍一条）。

### 3.6 点单、设定和完成的仪式感

- 点单：咖啡师的立绘已经有了但没用上。选完饮品后可以有一个「递过来」的瞬间，现在选饮品时已经会放对应的声音（`playDrinkCue`）。
- 设定：「把手机收起来」「打开电脑」现在是两个勾选按钮，可以各配一个小动作。
- 完成：盖章已经有动画，可以把它做成整页的收尾，然后是一段「起身离开」的过渡回到入口。回访时入口会显示「第 N 次来」和集点卡。

### 3.7 入口页

第一眼的文字偏多。可以让外景多露出来，把「推门进入」做成门本身；指针移动时背景有很轻的视差。隐私说明和反馈两个链接要留着，可以更安静。

### 3.8 手机

390px 宽度下沉浸感主要靠：背景铺满、混音器做成底部抽屉、倒计时够大、避开刘海和底部横条的安全区。专注时可以用 Screen Wake Lock 让屏幕不熄灭（纯浏览器功能，不发任何数据）。网站已经支持「添加到主屏幕」。

### 3.9 我不建议做的

- 不要按访客本地时间自动选时间档，用户明确否决过。
- 不要加第三套动画或画布库，Motion 和 PixiJS 已经够用。
- 不要从外部 CDN 加载字体、图片或脚本，隐私页承诺过。要换字体就把字体文件放进仓库。
- 不要做聊天或开放式角色扮演，也不要让提醒变成责备，这是路线图里的产品边界。
- 不要让带声音的视频自动播放；背景视频一律静音。

## 4. iPod 播放器在哪里

用户说这个设计不错，之后会用。它是一个 iPod 样子的爵士播放器：点按转盘、封面流、六个爵士电台、耳机线、九种机身颜色加自选色。

它已经在 `main` 上（PR #21，另一个 Claude session 做的），但只是原型，还没有接进网站，线上看不到。2026-10-07 用户决定：专注页里的音乐控制做成一个透明的播放器（规格在 `docs/hci-design.md` 7.6），不是 iPod；iPod 原型保留在仓库里，之后是否用在别处由用户定。

存放位置：

| 路径 | 内容 |
| --- | --- |
| `src/components/IPod/IPod.jsx` | 组件本体：机身、屏幕、封面流、点按转盘、耳机线、机身颜色。文案在文件顶部的 `IPOD_COPY`，中英文都有 |
| `src/components/IPod/covers.jsx` | 每个电台的封面图形 |
| `src/components/IPod/useStationPlayer.js` | 播放逻辑：一个 audio 元素，按顺序播放一个电台的曲目并循环，快放完时预加载下一首 |
| `src/components/IPod/ipod.css` | 全部样式。机身颜色由 CSS 变量 `--ipod-color` 决定 |
| `src/data/jazzStations.js` | 曲目表：6 个电台 44 首 |
| `ipod-preview.html` 和 `src/ipod-preview.jsx` | 单独的预览页 |

怎么看：`npm run dev`，然后在 dev server 的地址后面加 `/ipod-preview.html`。这个预览页只在开发模式下存在，不会被构建进线上的包。新 clone 的仓库里没有音频文件，所以能看外观和操作，但放不出声音；这台机器的主文件夹里有音频。

怎么用：`<IPod lang="zh" />`，`lang` 是 `zh` 或 `en`；可选的 `stations` 默认是 `JAZZ_STATIONS`。它只在浏览器里存一样东西：机身颜色，key 是 `cafe-focus-ipod-color`；不记上次的电台、曲目和音量。

操作方式：在转盘上转圈，封面页是选电台，播放页是调音量；中间键是选中或播放暂停；MENU 在两页之间切换；左右键是换台或上一首下一首；屏幕上可以左右拖封面或直接点封面。

现状和接进网站前要解决的事（细节在 `docs/progress.md` 的「暂时关闭的功能」）：

- 爵士功能现在是关着的（`src/lib/music.js` 的 `JAZZ_ENABLED = false`），混音器里显示「正在优化」。iPod 就是恢复爵士时要用的界面。
- 新曲库的音频还没有上传到 R2，上传由 Claude 这边做。在那之前线上放不出这 44 首。
- 尺寸：整机连耳机线是 420 × 600，专注页侧栏只有 300 像素宽。需要设计收起和展开两种形态，以及它在专注页里放在哪。这正是需要你来定的部分。做原型的 session 向用户提过一个方案：混音器里放一个小条，点开后浮出完整的 iPod。用户还没有确认，供你参考。
- 手机宽度还没有测过。420 宽在 390 的屏上会溢出，耳机线需要缩小或隐藏。
- 封面是用代码画的占位设计（`covers.jsx` 顶部的 `COVERS` 表），可以整套换掉，只要每个电台的 id 对应一张。曲名是按文件名起的，比较朴素，也有重名，可以重新起。
- 它已经尊重「减少动态效果」（耳机线不晃，封面不做过渡）。颜色用了 `color-mix()`，老浏览器会退回纯色。
- 它现在自己管音量和播放。接入时要和混音器、环境音总开关、倒计时结束联动，并且遵守「音乐只有一个槽位」：和 YouTube 电台互斥。
- 转盘用到方向键和空格，不要和专注页的快捷键（空格暂停、Esc）冲突。
- 界面上是否用 6 个新电台取代原来的三个歌单按钮，等用户决定。旧歌单的代码和文件不要删。
- 接入并打开 `JAZZ_ENABLED` 的那个 PR 里，要同时改冒烟测试里关于爵士的检查。

三点提醒：界面上它叫「爵士播放器」，没有出现 iPod 这个名字，建议保持；改它的外观没有问题，但用户喜欢的正是现在这种「可以拿在手里的物件」的感觉；音频文件不属于设计范围，上线用的是用户听过对比后选定的 128 kbps 版本，256 kbps 原版用户要求保留，两者都不要改。

## 5. 改的时候请保住的东西

这些不是审美上的意见，是会让线上出问题或违反用户规则的地方。

流程：

- 走分支加 PR，CI 的 `build` 通过后合并。合并后约一分半自动上线。
- 每次上线后跑 `scripts/smoke-test/smoke.mjs`（用法见同目录 README）。它靠下面这些文字和类名找元素，改了其中任何一个，要在同一个 PR 里更新脚本：按钮文字（`Enter the Café`、`Americano`、`Choose a seat`、`Window Seat`、`Sit down`、`Put my phone away`、`Open my laptop`、`Start Working`、`Pause`、`Resume`、`Visit again`、`Morning`、`Night` 和对应的中文），类名和 id（`.site-note a`、`#order-title`、`.ambience-switch`、`.task-field input`、`.setup-panel`、`.time-slots`、`.timer-display`、`.sound-slider`、`.layer-paused`、`.mixer`、`.mixer-toggle`、`.mixer-body`、`#focus-title`、`.status-message`、`.complete-panel`、`.eyebrow`、`.stamp`）。
- 大的结构改动可以用 `scripts/visual-check/` 做改动前后的逐状态对比。

行为：

- 第一次出声必须发生在用户的点击里，否则浏览器会拦截自动播放。现在是 `src/App.jsx` 的 `enterCafe` 在点击事件里调用 `sound.ensureAudio()`。如果把「推门」改成拖动或别的手势，要保证这一步仍然在用户手势的回调里。
- 倒计时按结束时间戳计算，逻辑在 `src/hooks/useFocusSession.js`。组件里不要自己再写计时。
- 刷新后恢复进行中的会话、空格暂停和继续、Esc 先暂停再结束、专注 25 分钟后的休息提议、集点卡，这些都在 hook 里，重做页面时接上同样的数据即可。
- 浏览器里存的东西都以 `cafe-focus-` 开头，读写用 `src/lib/storage.js`。
- 音乐只有一个槽位：爵士和 YouTube 电台互斥。
- 文案在 `src/data/copy.js`，中文和英文都要写。语气是轻、不责备、把人带回任务。

无障碍和动效：

- 系统开了「减少动态效果」时不要有位移和缩放，循环动画显示静止状态（`src/lib/reducedMotion.js`）。
- 现有的无障碍属性（`aria-pressed`、`aria-valuetext`、`aria-expanded`、进度点的场景名）是特意加的。把控件换成物件外观时，下面仍然要是真正的按钮和滑块，键盘能操作。

素材和体积：

- 图片放 PNG 母版，再用 `python3 scripts/convert-images.py` 生成 WebP，代码只引用 `.webp`。构建时会把 `public/assets/scenes/` 下的 PNG 和 `cafe-room.png` 从上线的包里去掉（`vite.config.js` 的 `dropPngMasters`），所以引用这些 PNG 线上会 404。其他目录的 PNG 会原样上线，人物设定图每张有几 MB，用之前先转成 WebP。`cafe-artifacts/` 不在 `public/` 下，里面的图要先放进 `public/assets/` 才能用。
- 现在主包约 245 KB（gzip 79 KB），样式约 16 KB。Motion 进主包约加 35 KB（gzip）。背景视频和大图会直接影响手机上的首屏，请控制大小。
- 不要重命名或删除已有文件，除非用户同意。

音频和隐私：

- 不要压缩、裁剪或替换音频。要加新的声音（包括界面音效）必须有允许公开网站使用的许可，先问用户，并登记到 `docs/audio-credits.md`。
- 不要引入会把访客数据发到服务器的东西。现在页面只会请求：本站、音频域名 `audio.tempomyplanner.com`、Cloudflare 的访问统计、Sentry 的错误上报，以及访客主动打开 YouTube 电台时的 `youtube-nocookie.com`。要加别的先问用户，并更新 `public/privacy.html`。

## 6. 需要运维配合的时候

下面这些事告诉 Claude（在 `docs/progress.md` 留言，或者让用户转达）：

- 新的音频，或者体积大的视频素材：需要上传到 Cloudflare R2 并设置缓存，不要放进仓库。
- 想加任何第三方服务或脚本。
- 冒烟测试因为你的改动需要大改。
- 上线后发现异常：回滚方法在 `docs/progress.md` 的「回滚」一节，先回滚再查原因。
